"Checked" in the directory only means a project's details are accurate, not that it works well. This page holds the tests: the same brief goes to different skills, the outputs are kept unedited, and they are compared blind so you can judge for yourself.

Round two is done (2026-10-18): 10 script-writing skills plus a control with no skill, three runs each on the same open brief, 33 runs in all. Every output, transcript, story card and the reasoning for every blind comparison is on GitHub (in Chinese).

Round two: an open brief

The brief says only "write a vertical short drama", plus the length (60 episodes of 1–2 minutes) and three deliverables: a character bible, a 60-episode outline with paywall points, and full scripts for episodes 1–3. No genre, characters or plot. Every run used Claude Code with claude-opus-5-5 at high effort and word-for-word identical prompts and replies, so the only variable is which skill was installed. Scripts that ship with a skill could run inside a system sandbox.

The review had two parts, and neither could see which skill wrote what. First, each draft got a story card, to see how alike the stories are. Then run n of each skill was compared with run n of the control, once for the scripts and once for the characters and outline. Each comparison was repeated with the order swapped, and a skill only counts as winning if it won both times.

Findings

  1. With a skill, scripts were mostly easier to shoot. In the script comparisons, 9 of 10 skills beat the control in most runs, and 5 won all three. They won on shootability, dialogue and AI tells: the control often packed four to eight scenes and flashbacks into an episode and ran past two minutes. The control's episode-ending hooks, though, were often stronger. shuohao-skills was the only one to lose all three.
  2. Characters and outlines split the field more. ai-short-drama, Shanyin Screenwriting Master, screenwriting-skills, zenstory and manju-laoli won all three runs, and Emma won two and tied one. qianqianwriting, hongguo, short-drama-factory and shuohao never beat the control outright, mostly for formulaic premises and overstuffed episodes. All 33 drafts put the first paywall at episode 10.
  3. Skills do change which story gets written. The 33 dramas fell into 21 story types. Two runs of the same skill landed in the same type 12% of the time; two runs of different skills, only 2.4%. hongguo, for example, wrote a daughter-in-law settling accounts with her in-laws all three times, and ai-short-drama wrote two dramas called The Old Brine.
  4. The model's defaults show up whichever skill is installed. 15 of the 33 drafts have a character named Xiaoman, written by 10 of the 11 entries, and 10 heroines have the surname Shen. zenstory and shuohao each wrote a drama called The Appraiser whose heroine is chief appraiser at the same fictional auction house. Distinctive names and premises still have to come from a person.
  5. Most skills do not ask you to pick a direction first. Across 33 runs, only a few runs of manju-laoli, Shanyin and shuohao stopped to offer several story options.
  6. Everything needs cleanup before it goes to a crew. Every skill's drafts carry IDs, runtime estimates, checkpoints or self-check tables mixed into the text.

Limits of this round

  • One model. The results only describe these skills under claude-opus-5-5; another model may differ.
  • Most skills did not ask for a direction. So the differences between runs come mostly from the model's own randomness. A real user's choice at that step might make the story more distinctive.
  • No network. For safety, the agent had no network and could not read files outside its own folder; skills that would check the charts had to rely on what they ship with.
  • The reviewers are AI. Story cards, story types and comparisons were all done by claude-opus-5-5, the same model that wrote the drafts. 85% of the quotes in the reviewers' reasoning appear word for word in the drafts. Next round we plan to add human screenwriters.

Round one: a rebirth-revenge premise (flawed design)

Round one used a detailed premise, Double-Sided Embroidery: a Suzhou embroidery heir breaks off her engagement at the banquet, for Hongguo, 60 episodes. 10 script-writing skills and a control ran once each, without scripts. The premise fixed the heroine, the rebirth point, the breakup, the fire and the ending, and each skill ran once, so the round cannot show whether skills change the story. This page used to say "the story skeletons converge, with or without a skill". That conclusion does not hold and has been removed; round two shows the shared names were mostly the model's defaults.

Single-run observations: the control's episodes ran 1.5–2 times the limit and the heroine's foreknowledge never failed; screenwriting-skills and Shanyin led on characters and dialogue. See the round one review · all outputs (in Chinese).

How we test

  1. The same input, as little as possible: the brief gives only the length and deliverables, with no genre, characters or plot, and every skill in the round shares it.
  2. The skill is the only variable: the same agent, model, reasoning effort and tool permissions, with versions recorded. The control just has no skill.
  3. Pinned skill versions: the commit of each repo at test time is recorded.
  4. Each skill's own process: the run opens by calling the entry skill. When a skill stops to ask, it gets the same fixed reply: if it offered several genres or story options, run n picks option n; everything else follows the skill's own recommendation.
  5. Skill scripts can run: commands run in a system sandbox with no network and no view of other entries' output.
  6. Three runs each, all kept: no cherry-picking.
  7. Blind review: reviewers do not know which skill wrote a draft, and every comparison is run in both orders.

What we look at

DimensionWhat it means
HooksDo the opening and each episode ending make you want the next one
DialogueDoes it sound like people talking, and do characters sound different
AI tellsHow much boilerplate, parallelism and empty adjectives
ShootabilityIs the runtime right, are the scenes and cast realistic, how much rework before shooting
CharactersAre motives clear, do characters have flaws and change, are side characters more than tools
FreshnessAre the premise and set pieces fresh or the usual formula
StructureDoes conflict escalate, do the twists hold, are there long sags
Paywall pointsAre they well placed, with enough of a hook before each

Reviews give observations and examples, with no overall scores. The runner is evals/run.py and the reviewer is evals/judge.py, so anyone can reproduce the method.
