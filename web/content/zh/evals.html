目录里的「人工核对」只说明项目信息准确，不说明好不好用。这一页放实测：同一份需求交给不同的 skill，把产出原样摆出来，再匿名盲比，让你自己判断。

第二轮已完成（2026-10-20）：11 个网文和短剧的选题 skill 加 1 个不装 skill 的对照组，给同一个爽文故事定选题，各定 3 次，共 36 次，所有参赛者两两盲比。全过程见第二轮实测记录，原始数据在 GitHub。

第一轮已完成（2026-10-18）：10 个剧本类 skill 加 1 个不装 skill 的对照组，同一份开放需求各跑 3 次，共 33 次。全过程都能查：第一轮实测记录里有给 agent 的全部输入、每次运行的每一步、评审看到的匿名稿、每一场盲比的提示词和判决，以及评审体检。原始数据在 GitHub。

第二轮：选题

需求是给一个新的爽文故事定选题，这个故事以后可以写成网文，也可以拍成竖屏短剧；只定选题，交一句话卖点和选题说明。题材、篇幅、平台都不给。参赛的是短剧和小说两个清单里能从零出选题的 skill，按星数挑了 11 个，加 1 个不装 skill 的对照组，都用 Claude Code、claude-opus-5-5、推理强度 high，开场指令和固定回复一字不差。skill 给出几个方案时，统一让它选自己最推荐的那个。

评审看不到选题出自谁：先给每份选题抽一张故事卡，看撞不撞题；再让 12 个参赛者两两比，第 n 次运行对第 n 次运行，先后顺序对调再比一次，两次都判它赢才算赢。赢记 1 分，平记 0.5 分，每个参赛者比 33 次，按积分排名。只看最终推荐的那个选题，看卖点、新意、冲突和爽点、续航、可执行五项，篇幅和市场分析不加分。主评审是 claude-opus-5-5；又请 GPT（gpt-6-astra）用一字不差的提示词重判一遍。

主要发现

  1. 两位评审的前四名是同样四个 skill，只是顺序不同。Opus 依次是 Tomsawyerhu/Chinese-WebNovel-Skill、webnovel-writer、bookflow-skill、ai-short-drama；GPT 依次是 bookflow-skill、ai-short-drama、webnovel-writer、Tomsawyerhu/Chinese-WebNovel-Skill。四个各有所长：Tomsawyerhu 给主角少见的法律职业身份，卖点最抓人，比如「十三年前，陆家逼死她爸、抄了她家；十三年后，法院摇号摇中了她，派她去抄陆家」，但法条要逐条核实；webnovel-writer 给金手指配有代价的规则，比如「只讨真账、多拿反噬」；bookflow-skill 先写一两万字的短篇测题，场景少、人物少，最好落地；ai-short-drama 的异能都有规矩，新意强，但三次都要特效或 AI 画面。
  2. 多数 skill 比不装定得好，但不是全部。不装 skill 的对照组，Opus 排第 7（6 个 skill 比它高），GPT 排第 10（9 个比它高）。对照组的一句话卖点直接，但新意和续航弱，三次定的选题都有 skill 写出了同一类故事。
  3. 垫底的两个，流程都从扫榜开始。两位评审都把 oh-story 和 chinese-longnovel-skill 排在最后两名。这两个 skill 定选题都要先联网查起点、番茄等平台的榜单；这一轮不能联网，它们都在稿子里写明了没拿到榜单数据。评审扣分不是因为缺数据（市场分析不加分），而是选题本身：评审一再说它们的底子是常见套路，比如「重生先知」「鉴宝逆袭」。联网时它们选得怎样，这一轮测不出来。
  4. 撞题很多。36 个选题分成 25 种故事类型。5 份的书名以「冷静期」开头；18 张故事卡提到「账」（讨账、查账、账本），12 个参赛者都写过。
  5. 模型的默认人名还在。36 个主角里 11 个姓许；叫「周砚」的角色出现在 4 个参赛者（含对照组）的稿子里。
  6. 没有一个 skill 先停下来让人挑方向。36 次运行都在第一轮就把选题写成了文件。

第一轮：开放题

需求只有一句「写一部竖屏短剧」，加上篇幅（60 集，每集 1–2 分钟）和三项交付：人物小传、60 集分集大纲（标出付费卡点）、第 1–3 集剧本。不给题材、人物和情节。所有组都用 Claude Code、claude-opus-5-5、推理强度 high，开场指令和固定回复一字不差，唯一的变量是装了哪个 skill。skill 自带的脚本可以在系统沙箱里运行。

评审分两部分，都看不到稿子出自谁：先给每份稿子抽一张故事卡，看各家的故事像不像；再把每个 skill 的第 n 次运行和对照组的第 n 次运行两两比，分剧本和人物大纲两项，先后顺序对调再比一次，两次都判它赢才算赢。主评审是 claude-opus-5-5；又请 GPT（gpt-6-astra）用一字不差的提示词重判一遍，两位评审结论不同的地方标「有争议」。

主要发现

  1. 装了 skill，剧本大多更能拍。剧本盲比里，10 个 skill 有 9 个在多数运行里赢了对照组，5 个三次全赢。赢在可拍性、对白和 AI 味：对照组每集常有四到八场戏，带闪回，篇幅超过 2 分钟。但对照组每集结尾的钩子常常更强。shuohao-skills 是唯一三次都输的，但 GPT 复核判它两赢一平，这一条有争议。两位评审都认为 10 个里有 9 个多数运行赢了对照组，只是 GPT 认为没赢的是 short-drama-factory。
  2. 人物和大纲分化更大。ai-short-drama、山音编剧大师、screenwriting-skills、zenstory、漫剧老李三次全赢，艾玛编剧两赢一平；qianqianwriting、hongguo、short-drama-factory、shuohao 三次里最多赢一次，主要输在设定套路化、单集塞得太满；GPT 复核只在 shuohao 上同意，另外三个有争议。33 份稿子的第一个付费卡点全在第 10 集。
  3. skill 会改变写什么故事。33 部剧分成 21 种故事类型。同一个 skill 的三次运行，两两落进同一类型的比例是 12%，不同 skill 之间只有 2.4%。比如 hongguo 三次都是全职儿媳清算婆家一类，ai-short-drama 两次都写了叫《老卤》的剧。
  4. 模型的默认偏好，换哪个 skill 都在。33 份里有 15 份有一个叫「小满」的角色，11 个参赛组里有 10 个写过；10 份的女主姓沈。zenstory 和 shuohao 各写了一部《掌眼》，女主都是「瀚古拍卖」的首席鉴定师。想要独特的名字和设定，要靠人来改。
  5. 大多数 skill 不会先让人挑方向。33 次运行里，只有漫剧老李、山音编剧大师和 shuohao 的个别几次停下来给出几个故事方案。
  6. 交给剧组之前都要清理。每个 skill 的稿子里都夹着编号、时长预估、检查点、自检表这类元数据。

怎么测

  1. 同一份输入，越少越好：需求只写篇幅和交付物，不给题材、人物和情节，所有参赛 skill 共用。
  2. 只有 skill 一个变量：同一个 agent、同一个模型、同样的推理强度和工具权限，记下版本号。对照组只是不装 skill。
  3. 固定 skill 版本：记下每个仓库测试时的 commit。
  4. 按 skill 自己的流程走：开场只调用入口 skill。skill 停下来问问题时，统一回复同一句话，其他问题按 skill 自己的推荐。给了几个题材或故事方案的，第一轮让第 n 次运行选第 n 个，好让三次写不同的故事；第二轮比的就是选题，改成选它最推荐的那个。
  5. 能跑 skill 自带的脚本：命令在系统沙箱里运行，不能联网，看不到其他参赛者的产出。
  6. 每个跑三次，全部保留：不挑最好的一次。
  7. 匿名盲评：评审看不到稿子出自哪个 skill，先后顺序对调各比一次。

维度看什么
钩子开头和每集结尾能不能让人想往下看
对白像不像人说的话，角色之间有没有区别
AI 味套话、排比、空洞形容词多不多
可拍性时长对不对，场景和演员数量是否合理，离能直接拍还差多少修改
人物动机清不清楚，有没有缺点和成长，配角是不是工具人
新意设定和桥段有没有新鲜感，是不是常见套路
结构冲突升级、反转成不成立，有没有连续塌腰
卡点付费卡点卡得准不准，卡点前有没有足够的钩子

第二轮比选题，看五项：卖点（一句话卖点能不能让人立刻想看）、新意（是不是常见套路换个名字）、冲突和爽点（主角要什么、谁挡着、爽点能不能一直供得上）、续航（按它自己打算的篇幅撑不撑得住）、可执行（写得下去、拍得出来，有没有明显的审核风险）。

点评只写观察和例子。第一轮不打总分；第二轮两两全比，按积分排了名次。运行器是 evals/run.py，评审是 evals/judge.py，任何人都可以按同样的方法复现。
